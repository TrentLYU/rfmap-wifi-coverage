## 1. 概述与用户

| 项 | 内容 |
|---|---|
| 问题摘要 | 刚搬进新房间的用户想知道"这屋的 Wi-Fi 各处怎么样"，但逐点测完一整间房太费时间，而且没有一个可信的指标说明"测了几个点推出来的图靠不靠谱"。 |
| 目标用户 | **主要**：刚搬入新宿舍/出租屋的学生或租户（自己动手布置一台路由器）。**次要**：家庭组网/装维与售后诊断人员。 |
| 预期价值 | 用户只需在**少量点位**采一次 RSSI，就得到**整间房**的覆盖热力图，并知道这份图的误差有多大（MAE/RMSE，单位 dB），从而判断"哪里信号最差""路由器换个位置有没有变好"。 |
| 关联证据 | 见 [`docs/01-Proposal.md`](01-Proposal.md) 第 3 节：E-01（采集链路可用）、E-02（RSSI 对位置敏感且需规范摆放）、E-03（逐点采集流程已跑通，ROOM-A-dp1 进行中）、E-04（场地与网格规模）、E-05（需求来源）、E-06（逐点全测的人工成本）。 |
| 用户不做的部分 | 用户**不需要**了解网络结构、损失函数或插值方法；用户只需要"输入几个测点 → 拿到图和误差"。 |

## 2. MVP 范围（5 个核心功能）

| 编号 | 核心功能 | 一句话行为描述 | 为什么主用户任务必需 | 优先级 |
|---|---|---|---|---|
| F-1 | **测点采集与留档** | 在给定点位清单上逐点采集 RSSI，输出该点的均值/中位数/标准差，并连同房间、坐标、高度、AP 标识、时间一起落盘 | 没有**可信且可追溯**的实测点，后面的图就是凭空画的；同一份部署必须可复查 | 必须 |
| F-2 | **房间与点位配置** | 录入房间范围、接收高度与坐标约定，生成该房间的点位清单（可先只列出不采集） | 预测结果必须落在**统一的坐标与网格**上，否则"某个位置"无法对齐、也无法比较两次部署 | 必须 |
| F-3 | **数据划分（场景组 + 输入点/隐藏点）** | 按部署把地图分成训练/验证/测试组；在每张图内分出"给网络的输入点"和"用作答案的隐藏实测点"，划分结果固定并保存 | **这是"能不能证明预测准"的前提**：不划分就没有答案，还会因为同图泄漏得出虚高结论 | 必须 |
| F-4 | **覆盖预测** | 只给房间信息与输入点，输出与房间网格同尺寸的整张 RSSI 数值图（未测位置由模型补全） | 这是用户价值本身：把少量点变成整间房 | 必须 |
| F-5 | **结果展示与精度报告** | 把预测值还原为 dBm：输出带统一色标的热力图（标出输入点、隐藏点与隐藏点误差），并报告 MAE/RMSE（dB）、推理时间与简单插值基线的对比 | 用户要的是"哪里差、可不可信"，不是一串数字；报告让结论可复查、可对质 | 必须 |

> 不设"应该"级功能：以上 5 项任一缺失，主用户任务都无法闭环（要么没有输入、要么没有答案、要么没有结论）。若进度吃紧，**砍掉的应是排除项里的内容**，而不是这 5 项。

## 3. 排除项（Out of Scope）

课程要求：明说"没有需求支撑就不要加认证、数据库、支付、微服务、公网托管、AI 功能"。

| 候选功能 | 排除/推迟 | 理由（与 MVP 价值的关系） |
|---|---|---|
| **户型推断 / 房间划分**（上位课题的核心） | 推迟 | 立项表的上位课题是多房间结构重建；本轮 MVP 的房间范围**由人工提供**（任务书原文："房间范围和测点坐标由人工提供，第一版不要求输入详细家具布局"）。先把"已知房间的覆盖预测"做扎实，再谈结构推断 |
| **多频段（5 GHz / 6 GHz）覆盖** | 排除 | 硬件限制：ESP32-C6 只支持 2.4 GHz（BR-01）。承诺多频段无法验证 |
| **家具布局 / 墙体材质反演** | 推迟 | 需要更多场景与更强的标注成本；当前证据（E-04）不足以支撑 |
| **随门开关、家具移动、人员遮挡的动态更新** | 推迟 | 任务书明确本阶段不要求；且需要区分"短时遮挡"与"持续布局变化"，超出 3–5 页需求可描述的范围 |
| **以 CSI 作为预测目标** | 推迟 | 任务书规定第一版**以 RSSI 为预测目标**；CSI 可同步保存留作后续 |
| **跨房间泛化 / 多户型结论** | 推迟（但保留结论边界说明） | 我们只有一间房间。任务书明确：同房间新部署**不能**代替跨房间测试（BR-15） |
| 云端上传 / 公网托管 / 数据库 / 账号体系 | 排除 | 全部在局域网内完成，单机单用户；引入后不改变被测行为（参见 [`docs/04`](04-Agent-Decision-Record.md) AD-01、AD-02） |
| 手机 App / 独立前端界面 | 推迟 | 本轮**正式路径是命令行脚本**（见 4.2）；做一个 App 不提升预测能力 |
| 大模型 / 在线推理服务 | 排除 | 产品不含云端 AI：预测由本地训练的小型卷积网络完成，无按次计费、无数据外发 |

## 4. 用户旅程与原型

### 4.1 端到端主流程

```
① 部署固定        用户把路由器放在房间一角并全程不动；量房间尺寸，约定坐标（路由器所在角为原点 (0,0)）
       │           决策点 D-1：房间范围与网格间距取多少？
       ▼
② 生成点位清单    运行采集脚本 --grid x0,y0,x1,y1,step --dry-run → 屏幕列出本次要采的点位（数量、坐标）
       ▼           决策点 D-2：这份清单是否覆盖房间各区域？点位太少/太靠一边 → 调整网格
③ 逐点采集        「放入设备（统一高度与朝向）→ 人退到固定位置 → 稳定 3 s → 采样 20 s → 落盘」
       │           每点屏幕回显：均值/中位数/标准差/范围 + 判定（太近 / 合适 / 偏弱）
       ▼           决策点 D-3：是否出现"整份都太近或偏弱"？→ 是则重采（未采完可中断，重跑自动续采）
④ 换部署再采      挪动路由器位置 → 换 map_id → 重复②③（≥3 份独立部署 = 3 份参考地图）
       ▼
⑤ 数据划分        按部署整组划分 train/val/test；每张图内分「输入点 / 隐藏实测点」；划分文件保存（固定不变）
       ▼           决策点 D-4：输入点取几个、怎么分布？→ 至少测两组（如 8 点 / 15 点）看误差怎么变
⑥ 训练与选择      用输入点训练；只在隐藏实测点上算损失；按验证集选最佳权重并保存训练/验证曲线
       ▼           决策点 D-5：三个方案（卷积补全自编码器 / 小 U-Net / 插值引导残差 U-Net）选哪个交付？
       │              依据验证集表现，测试集只在最后评估用一次
       ▼
⑦ 推理出图        只给房间信息 + 输入点（坐标 + RSSI）→ 输出整张二维 RSSI 网格 → 还原为 dBm → 热力图
       ▼
⑧ 拿到结论        用户看到：哪里信号最差（深色区域）、换成新路由器位置后有没有改善、这张图的 MAE/RMSE 是多少、
                  与"只用同样几个点做插值"相比好多少。数据、划分文件与模型权重都可复查。
```

**（非 UI 项目的等价"输入 → 输出"工作流）**

```
输入：房间范围 + 网格间距 + 接收高度 + 若干个「已知点位坐标与其 RSSI」
  ↓（模型，不读取任何参考答案）
输出：同尺寸二维 RSSI 数值图（dBm）+ 热力图 + MAE/RMSE 报告 + 推理时间
```

### 4.2 关键交互点（本项目的"界面"）

| 编号 | 交互点 | 用户在这里做什么 | 期望反馈 | 位置 |
|---|---|---|---|---|
| U-1 | 点位清单预览 | 输入房间网格参数，先看要采哪些点 | 打印点位总数与逐个坐标；提示"去掉 `--dry-run` 加 `--ip` 即开始采集" | 采集脚本（命令行） |
| U-2 | 逐点采集回显 | 放设备、退开、按回车 | 进度百分比、当前点已采样数、失败次数；该点结束后回显均值/中位数/标准差与判定 | 采集脚本 |
| U-3 | 整份地图摘要 | 一份地图采完（或被中断） | 本次新增点数、均值范围、**不在 -40~-70 dBm 的点位清单**（提示但不删除） | 采集脚本 |
| U-4 | 划分结果查看 | 检查输入点/隐藏点是否合理 | 打印每张图的输入点数、隐藏点数与坐标分布；划分文件已保存 | 划分脚本 |
| U-5 | 训练过程 | 观察误是否下降 | 训练/验证曲线（分别保存），当前最佳权重路径 | 训练脚本 |
| U-6 | 热力图与误差图 | 看结论 | 统一色标的 RSSI 热力图 + 输入点/隐藏点标记 + 隐藏点误差表 | 推理/绘图脚本（输出图片文件） |

> **MVP 的正式路径 = 命令行脚本**（`lab-tools/` 采集 + 训练/推理脚本）：无外网也能全程完成（BR-13）。
> 官方浏览器工具页**仅作为设备与链路排查的辅助入口**（看实时读数、确认频段），**不属于 MVP 交付路径**——它依赖外网与指定浏览器版本。

### 4.3 重要决策点

| 决策点 | 用户面临的选择 | 系统应如何帮助决策 |
|---|---|---|
| D-1 | 房间范围与网格间距取多少 | 提供 `--dry-run` 预览点位总数与坐标；对房间过大/网格过密给出预计耗时提示 |
| D-2 | 这家份地图的点位是否够用 | 采集前显示点位分面；采集后统计有多少区域完全没有测点（不替代插值结论，只做覆盖提示） |
| D-3 | 这份地图是否需要用 | 对该份地图整体判定：**整份过强/过弱 → 提示重采**；个别点异常 → 保留原始数据并标注，不删除（BR-04） |
| D-4 | 输入点取几个、怎么分布 | 报告"误差随输入点数量/分布的变化"，让用户看到"再多测几个点能好多少" |
| D-5 | 三个方案交付哪个 | 只按**验证集**表现选择；测试集只在最后评估一次；**不承诺神经网络必然优于插值** |

## 5. 功能需求（Functional Requirements）

### 5.1 F-1 测点采集与留档

| ID | 需求 | 可观察的行为描述 | 优先级 | 关联 |
|---|---|---|---|---|
| FR-01 | 设备与链路自检 | 采集前能返回设备身份（型号/固件类型/版本）、在线状态与网络信息；**频段不等于 2.4 GHz 时给出明确告警** | 必须 | F-1 / BR-01 |
| FR-02 | 链路质量判定 | 能读到当前 RSSI，并判定为"太近（> -40）/ 合适（-40~-70）/ 偏弱（< -70）"三类之一 | 必须 | F-1 / BR-04 |
| FR-03 | 单点采集与统计 | 对某个点位连续采样指定时长，输出该点的 **均值、中位数、标准差、最小/最大值与有效样本数** | 必须 | F-1 |
| FR-04 | 参考地图落盘 | 一份部署 = 一份参考地图：逐点追加写入 CSV（含 `map_id / room / x_m / y_m / height_m / ap_id / ssid / band / channel / 统计量 / 时间戳 / 采集人`），并生成元数据文件（网格、每点时长、设备信息、开始时间） | 必须 | F-1 |
| FR-05 | 断点续采 | 采集被中断后，用同一条命令重跑会**跳过已记录的点**，只补齐剩余点位，且不产生重复行 | 必须 | F-1 |
| FR-06 | 采集质量告警 | 出现不在 -40~-70 dBm 的点时打印清单与原因提示；单点采样全部失败时提示"先排查链路再重跑" | 必须 | F-1 / BR-04 |

### 5.2 F-2 房间与点位配置

| ID | 需求 | 可观察的行为描述 | 优先级 | 关联 |
|---|---|---|---|---|
| FR-07 | 点位清单生成 | 支持按网格（`x0,y0,x1,y1,step`）或手工点位生成清单；预览模式下**不连接设备**，只打印点位总数与逐个坐标 | 必须 | F-2 |
| FR-08 | 房间与网格信息登记 | 房间名、接收高度、AP 标识随地图一起记录，并作为推理时必填的输入 | 必须 | F-2 / BR-09 |

### 5.3 F-3 数据划分

| ID | 需求 | 可观察的行为描述 | 优先级 | 关联 |
|---|---|---|---|---|
| FR-09 | 场景组划分 | 按部署（`map_id`）把参考地图整组分配到训练/验证/测试集，输出并保存划分文件 | 必须 | F-3 / BR-06 |
| FR-10 | 输入点 / 隐藏实测点划分 | 在每张图内分出输入点与隐藏实测点；**两者交集为空**；划分结果固定并保存；训练阶段可反复改变抽点方式，但验证与测试的划分必须固定 | 必须 | F-3 / BR-06 |
| FR-11 | 划分自检 | 划分后能检查并报告：同一 `map_id` 是否跨集合、输入点与隐藏点是否有重叠、每张图隐藏点数量是否够算误差 | 必须 | F-3 / BR-06 / BR-11 |

### 5.4 F-4 覆盖预测

| ID | 需求 | 可观察的行为描述 | 优先级 | 关联 |
|---|---|---|---|---|
| FR-12 | 训练输入构造 | 输入为同尺寸的三通道图：稀疏 RSSI 图、观测位置标记图、房间有效区域图；**未测位置是占位值，不得被当成 0 dBm 或"无信号"**；房间外使用填充标记 | 必须 | F-4 / BR-08 |
| FR-13 | 标准化参数 | 标准化只用**训练集**统计量计算，并随模型一起保存；推理时复用同一组参数 | 必须 | F-4 / BR-07 |
| FR-14 | 训练与选优 | 三个方案共用同一数据接口与评价规则；只在隐藏实测点上计算误差并按有效监督点数量归一化；保存训练/验证曲线与最佳权重 | 必须 | F-4 |
| FR-15 | 稀疏点预测整图 | 推理只需房间信息与输入点（坐标 + RSSI），输出与网格同尺寸的单通道 RSSI 网格；**推理进程不得读取任何隐藏实测点或参考答案** | 必须 | F-4 / BR-05 |

### 5.5 F-5 结果展示与精度报告

| ID | 需求 | 可观察的行为描述 | 优先级 | 关联 |
|---|---|---|---|---|
| FR-16 | 数值还原与热力图 | 预测值还原为 dBm 并绘制热力图；图中标出输入点与隐藏实测点，并使用**统一颜色标尺**便于对比 | 必须 | F-5 / BR-10 |
| FR-17 | 精度报告 | 在测试场景的隐藏实测点上报告 **MAE 与 RMSE（单位 dB）**，同时给出推理时间 | 必须 | F-5 |
| FR-18 | 插值基线对比 | 用**同一组输入点**的简单插值结果作为基线，与网络预测并排比较；纯插值结果单独保留 | 必须 | F-5 |
| FR-19 | 输入点敏感性 | 在相同测试场景下改变输入点数量与分布，报告误差如何变化 | 应该 | F-5 / D-4 |
| FR-20 | 模型可重新加载 | 训练进程结束后能重新加载（最佳权重 + 模型结构 + 标准化参数 + 网格配置）并生成同口径的整张地图 | 必须 | F-5 |

## 6. 业务规则与边界情况

课程要求的覆盖面：权限、校验、冲突动作、空状态、非法输入、失败行为。

| ID | 规则 | 触发条件 | 期望行为 | 依据 |
|---|---|---|---|---|
| BR-01 | 只支持 2.4 GHz | 读到频段不是 2.4 GHz | 明确告警并提示重新配网；不得继续把数据当有效 | 硬件限制（ESP32-C6） |
| BR-02 | 设备与采集电脑必须同网段 | 不同网段 / 路由器开启 AP 隔离 | 提示"检查网络"，**不得误判为设备故障** | 实测（E-01） |
| BR-03 | 采集规范不可变 | 采集一份地图期间 | 路由器位置/配置全程不动，只移动采集设备；各点**统一接收高度与朝向**；采点人员退到固定位置，不站在设备与路由器之间 | 任务书"数据怎样采集"；实测（E-02） |
| BR-04 | 有效区间判定与"不删点" | 某点均值 > -40 dBm 或 < -70 dBm | 标注为"太近/偏弱"并提示原因；**原始实测数据一律保留**，不得删除或用插值结果替换 | 任务书；实测（E-02、E-04） |
| BR-05 | 不得用插值结果充当实测答案 | 任何构造监督答案的场合 | 隐藏实测点必须来自真实采集；插值结果只能作为基线或残差方案的初始图，不能作为答案 | 任务书明确要求 |
| BR-06 | 防泄漏 | 划分与训练时 | 同一 `map_id` 的重复记录与不同遮挡版本**必须放在同一集合**；隐藏实测点不得进入输入 | 任务书；FR-09~FR-11 |
| BR-07 | 标准化只用训练集 | 构造训练输入 | 标准化参数只从训练集计算并保存；测试集不得参与调参 | 任务书 |
| BR-08 | 未测位置 ≠ 0 信号 | 构造输入图 | 未测位置只作占位，必须有观测标记区分；完全未测位置与房间外位置**不参与误差计算** | 任务书（否则会把"没测"学成"没信号"） |
| BR-09 | 网格配置随模型保存 | 推理阶段 | 推理必须使用训练时的同一网格间距、房间范围与接收高度；不一致时拒绝出图并说明 | FR-08 / FR-20 |
| BR-10 | 单位统一 | 报告与界面 | RSSI 一律以 **dBm** 表示，误差一律以 **dB** 表示；还原到 dBm 后才做报告 | 任务书"效果怎样判断" |
| BR-11 | 空状态 | 尚无任何地图数据 / 某张图隐藏点为 0 | 给出明确的空状态说明与下一步指引，**不报错崩溃、也不产出空图** | 课程要求覆盖空状态 |
| BR-12 | 非法输入 | 不存在的设备 IP、非法网格参数、格式错误的点位 | 给出可理解的错误并退出（非零退出码），不静默失败 | 课程要求覆盖非法输入 |
| BR-13 | 无外网可用 | 采集或推理时没有外网 | 采集、划分、训练、推理、出图全流程在局域网/本机完成 | NFR-06 |
| BR-14 | 凭据不入库 | 任何时候 | Wi-Fi 口令等凭据不得写入仓库；采集记录中的"采集人"可用代号 | AGENTS.md 硬性约束 |
| BR-15 | 结论边界必须如实 | 报告结果 | 只在**同一房间的新部署**上测试时，结论必须限定为"该房间的新部署"；不得表述为跨房间/全屋型通用 | 任务书明确要求 |
| BR-16 | 结果异常好时的自查 | 验证误差远低于训练误差，或测试误差异常小 | 触发自查提示：同图泄漏、隐藏点进入输入、插值使用了完整参考数据 | 任务书"效果怎样判断" |
| BR-17 | 采集前必须自检 | 开始采集前 | 未通过设备自检与频段检查时不得开始批量采集 | FR-01 / BR-01 |

## 7. 验收标准（Acceptance Criteria）

### 7.1 格式

```
给定【前置条件】，
当【执行的动作】，
则【可观察的结果】，且【不应发生的事】。
```

### 7.2 验收标准表

| ID | 对应需求 | 场景 | 类型 | 检查方式 | 结果 |
|---|---|---|---|---|---|
| AC-01 | FR-01 | 给定设备已上电且与电脑同网段，当执行自检，则返回型号、固件类型与版本，且读到 `band=2g`、信道与 RSSI | 成功 | 自检命令输出 | 已实测（`ESPectre Native 3.0.0 / esp32c6`，信道 11） |
| AC-02 | FR-02 | 给定链路正常，当读取 RSSI，则给出三档判定之一，且 RSSI 落在 -40~-70 dBm 时判为"合适" | 成功 | 自检/采集输出 | 已实测（-22 dBm 判"太近"；-51~-57 dBm 判"合适"） |
| AC-03 | FR-07 | 给定网格参数 `0,0,6,4,1`，当用预览模式运行，则打印 **35 个点位**与逐个坐标，且**不连接设备** | 成功 | 预览输出 | 已实测（35 点） |
| AC-04 | FR-03 / FR-04 | 给定设备在线，当完成 ≥5 个点位的采集，则 CSV 行数 = 已采点数，每行含均值/中位数/标准差且有效样本数 > 0；元数据文件存在且含 `map_id / height / grid / started_at / device` | 成功 | 文件校验 | ❓待实测（`ROOM-A-dp1` 仅产出元数据，CSV 未产出） |
| AC-05 | FR-05 | 给定一份地图已采若干点后中断，当用同一条命令重跑，则只补采剩余点位、CSV 不出现重复坐标行 | 成功 | 运行两次并比对行数 | ❓待实测（本地模拟设备已通过，真机待验） |
| AC-06 | FR-06 | 给定某点均值高于 -40 dBm，当该点采完，则打印"太近"提示与该点坐标，且该行**仍保存在 CSV 中** | 失败/告警 | 文件校验 | ❓待实测 |
| AC-07 | FR-09 / FR-10 | 给定 ≥3 份地图，当执行划分，则输出并保存划分文件，且检查通过：任一 `map_id` 只出现在一个集合；输入点与隐藏点**交集为空** | 成功 | 划分文件 + 自检输出 | ❓待实测 |
| AC-08 | FR-11 | 给定人为把同一份地图的记录放进两个集合，当执行划分自检，则**报出错误**并指出冲突的 `map_id` | 失败 | 故意构造冲突 | ❓待实测 |
| AC-09 | FR-12 / BR-08 | 给定输入图中有未测位置，当构造训练输入，则未测位置带观测标记，误差仅在隐藏实测点上计算，且未测位置**未参与损失** | 成功 | 训练日志与掩码检查 | ❓待实测 |
| AC-10 | FR-13 | 给定训练集已定，当完成一次训练，则标准化参数文件只包含训练集统计量，且推理复用同一文件 | 成功 | 参数文件核对 | ❓待实测 |
| AC-11 | FR-14 | 给定固定的少量训练样本，当训练若干轮，则训练误差**下降** | 成功 | 训练曲线 | ❓待实测（任务书要求的前置预检） |
| AC-12 | FR-15 | 给定只提供房间信息与输入点，当执行推理，则输出与网格同尺寸的 RSSI 网格，且推理进程在**读不到隐藏实测点文件**的情况下仍能出图 | 成功 | 移走答案文件后运行 | ❓待实测 |
| AC-13 | FR-16 | 给定一份推理结果，当出图，则热力图与误差图使用同一色标，且输入点与隐藏点在图上有可区分标记 | 成功 | 检查输出图片 | ❓待实测 |
| AC-14 | FR-17 / FR-18 | 给定测试场景与固定输入点，当执行评估，则报告 MAE 与 RMSE（dB）、推理时间，以及**同一组输入点**的插值基线对比 | 成功 | 评估报告 | ❓待实测 |
| AC-15 | FR-20 | 给定训练已结束（进程已退出），当重新加载保存的模型与配置，则能对同样的输入生成同样的地图 | 成功 | 重新加载后重跑一次 | ❓待实测 |
| AC-16 | BR-04 | **失败用例**：给定整份地图所有点都高于 -40 dBm，则判定该份"过强、无效"并提示重采，且**不报告为"信号优秀"或"设备故障"** | 失败 | 采集摘要输出 | ❓待实测 |
| AC-17 | BR-11 / BR-12 | **失败用例**：给定数据目录为空、或网格参数非法，则给出明确说明并以非零码退出，不产出空图 | 失败 | 命令输出与退出码 | ❓待实测 |

| AC-19 | BR-15 | 给定测试只覆盖同一房间的新部署，当生成报告，则报告文字明确限定结论范围，不出现"跨房间/通用"表述 | 成功 | 报告核对 | ❓待实测 |

## 9. 成功度量与完成定义

课程明确区分：**验收标准（AC）= 系统行为是否符合规格**；**成功度量（SM）= 它是否真的帮到用户**。
度量方法与目标**必须在测试前设定**，并**如实报告实际结果**。

| ID | 成功度量 | 评估方法 | 预设目标 | 何时测 | 实际结果 |
|---|---|---|---|---|---|
| SM-01 | 用户能不能自己做出这张图 | 让 1–3 名非团队成员（新入住学生/租户）按文档操作，观察是否需人帮助；结束后请他说出"哪个区域信号最差" | 预设：**≥2/3 无需帮助**完成，且能正确指出热力图中的最弱区域 | 【待填】 | 【待填】 |
| SM-02 | 这张图准不准 | 测试场景隐藏实测点上的 MAE/RMSE，与**同一组输入点**的简单插值基线对比 | 预设：**MAE 不劣于插值基线**；绝对值目标待首份地图采集后用同点位重复采样的 RSSI 标准差（`rssi_std`）作参照设定。**不承诺网络必然优于插值** | 【待填】 | 【待填】 |
| SM-03 | 相比逐点全测省了多少 | 对比"全网格逐点测"与"少量输入点 + 预测"的采集人时与点数 | 预设：完成一间房一份地图 **≤30 分钟**；输入点从全网格（实验场地 2 m 网格 49 点）降到 **8–15 点** | 【待填】 | 【待填】 |
| SM-04 | 换部署后还有效吗 | 在同一房间的**另一套路由器部署**上重复 SM-02 | 预设：新部署上仍能给出与插值基线相当或更好的结果；若明显退化，需如实报告并限定结论 | 【待填】 | 【待填】 |

**MVP 可演示的完成定义（Definition of Done）**
