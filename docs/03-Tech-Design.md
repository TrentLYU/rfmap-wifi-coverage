## 1. 系统结构

### 1.1 组件与数据流（本项目实测拓扑 + 本轮新增链路）

```
        ┌─────────── 2.4 GHz 局域网（采集与推理全程不需要外网）───────────┐
        │  路由器/热点：局域网互通、关闭 AP 隔离、位置全程不动              │
        └──────┬────────────────────────────────────────┬───────────────┘
               │ Wi-Fi 2.4G (3~5 m)                     │ Wi-Fi 2.4G
      ┌────────┴───────────────┐            ┌───────────┴─────────────────┐
      │ ESP32-C6-DevKitC-1-N8  │            │ 电脑（macOS + Python 3）      │
      │ 固件 ESPectre Native   │◄── HTTP ───│  ★正式路径：lab-tools/ 脚本   │
      │      3.0.0 (IDF 5.5.5) │   :62587   │   ┌── ① rssi_survey.py 采集   │
      │ 本地 HTTP :62587       │            │   ├── ② split 划分（未实现）  │
      │ 内置流量激励           │            │   ├── ③ train 训练（未实现）  │
      └────────────────────────┘            │   ├── ④ infer 推理（未实现）  │
                                            │   └── ⑤ 热力图/报告（未实现） │
                                            │  （浏览器工具页仅作链路排查）  │
                                            └──────────────────────────────┘
                                                          │
                    data/rfmap/*.csv+.meta.json ──②──► splits/*.json ──③──► models/<run>/ ──④──► outputs/rfmap/<run>/
```

> **正式路径 = 命令行脚本**：无外网也能完成采集→划分→训练→推理→出图（BR-13）。
> 官方浏览器工具页（`espectre.dev`）**只用于设备/链路排查**，不在 MVP 交付路径上（它是同一数据源 :62587，但依赖外网与 Chrome 151+）。

### 1.2 组件职责

| 组件 | 职责 | 支撑需求（PRD v1.0） |
|---|---|---|
| ESP32-C6-DevKitC-1-N8 | 普通 Wi-Fi 设备连上 AP，接收无线帧并提供链路 RSSI（CSI 可选） | FR-01、FR-02 |
| ESPectre Native 3.0.0 固件 | 连 Wi-Fi、在局域网开 HTTP 接口、内置流量激励、提供 CSI | FR-01、FR-03 |
| 设备 HTTP 服务（`:62587`） | `/health`、`/wifi`（RSSI/频段/信道）、`/diagnostics`、`/csi` | FR-01、FR-02、FR-03 |
| `lab-tools/rssi_survey.py` | 点位清单生成、逐点采样统计、CSV+元数据落盘、断点续采、质量告警 | FR-03~FR-08（**已实测**） |
| 划分脚本（**未实现**） | 场景组划分 + 图内输入点/隐藏点划分 + 划分自检 | FR-09~FR-11 |
| 训练脚本（**未实现**） | 三通道输入构造、标准化、三方案训练、最佳权重保存 | FR-12~FR-14 |
| 推理与出图脚本（**未实现**） | 仅凭输入点输出整张 RSSI 网格、还原 dBm、热力图与报告 | FR-15~FR-20 |
| 电脑 + `lab-tools/parse_events.py` 等 | 第一阶段 CSI 能力（仍可用，非本轮主线） | 第一阶段遗留 |

### 1.3 数据通路

| 通路 | 方向 | 内容 | 本次角色 |
|---|---|---|---|
| 控制/读数通路 | 电脑 → 设备 | 读 `/health`、`/wifi`（含 `rssi_dbm`）、`/diagnostics` | **主线数据源**：每个点位的 RSSI 样本 |
| 原始 CSI 通路 | 设备 → 电脑 | 二进制 CSI（首 4 字节 `ESPR`，8 s ≈ 200 KB） | 可选（OQ-03）；与运动检测互斥 |
| 事件通路 | 设备 → 电脑 | SSE 运动事件流 | 第一阶段遗留，本轮不参与 |

### 1.4 外部依赖约束（易踩坑）

| 约束 | 说明 |
|---|---|
| 跨源要求 | 设备接口**要求请求带 `Origin: https://espectre.dev`**；curl 无跨源限制，命令行不受影响。（已实测） |
| 频段 | ESP32-C6 **只支持 2.4 GHz**；读到 `band≠2g` 必须告警（BR-01） |
| 网段与隔离 | 设备与电脑必须同网段且关闭 AP 隔离；否则表现为"网络正常但连不上"（BUG-04 的掩码坑） |
| 数据来源可追溯 | 来源不明的历史数据（如 `data.xlsx`）**不得**当训练数据（PRD OQ-02） |

## 2. 技术选型

| 编号 | 组件/环节 | 选择 | 为什么适配（技能/设施/约束） | 更简单的替代方案 | 为什么不选它 |
|---|---|---|---|---|---|
| DR-01 | 采集硬件 | ESP32-C6-DevKitC-1-N8 | 课程已配发，已实测可读 RSSI/CSI | 手机或笔记本网卡测 RSSI | 读数口径不一致，且无法固定高度/朝向 |
| DR-02 | 固件 | ESPectre **Native 3.0.0**（IDF v5.5.5） | 开箱提供 Wi-Fi + 本地 HTTP + CSI，无需自研固件 | 自己写 ESP-IDF 固件 | 工期不可控，且不提升预测能力 |
| DR-03 | 主串口 | 板上标 **USB** 的原生 USB Serial/JTAG（`/dev/cu.usbmodem101`） | 实测日志与 Improv Serial 都在此口 | 标 `UART` 的 CP2102N 口 | 实测该口无输出，是"配网反复失败"根因（BUG-01） |
| DR-04 | 采集数值口径 | 单点连续采样后取**均值 + 中位数**，同时保存**标准差/极值/样本数** | 任务书要求"以统计值作代表、同时保留波动"；标准差是设定误差目标的天然参照 | 只读一次 RSSI | 单次读数不可复现、无法判断稳定性 |
| DR-05 | 采集实现 | Python 3 **标准库**脚本 + `urllib` | 环境已有 Python 3.9.6，无需额外安装；无外网可用 | 引入 requests/pandas | 增加依赖风险，对当前需求不必要 |
| DR-06 | 预测模型框架 | **PyTorch + `segmentation_models_pytorch`**（任务书推荐的 U-Net 实现路径） | 任务书指定；编码-解码结构天然匹配"稀疏输入→稠密输出" | 从零手写 U-Net | 易在特征拼接/上采样处出错，浪费在非核心难点上 |
| DR-07 | 主模型 | **小型 U-Net**（输入 3 通道 → 输出 1 通道，线性输出 + 回归损失） | 任务书指定为主方案；输入输出同尺寸，无需改结构 | 先上残差 U-Net | 残差方案依赖插值引导，复杂度更高，留作对照 |
| DR-08 | 对照方案 | ① 卷积补全自编码器 ② 插值引导残差 U-Net ③ **纯插值** | 三者共用同一数据接口与评估口径，才能说明"网络是否值得" | 只交一个模型 | 无法回答"更简单做法够不够"，无法解释误差来源 |
| DR-09 | 存储 | **本地文件系统**（`data/rfmap/`、`models/`、`outputs/rfmap/`） | 单场地单设备、数据量小（一份地图 35 行）；文件可直接复查 | 数据库（SQLite/Postgres） | 无多用户并发与查询需求，属课程明示"无需求不要引入" |
| DR-10 | 标准化与划分 | 标准化参数只从**训练集**计算并随模型保存；划分按**部署（`map_id`）整组** | 任务书硬性要求；否则测试结论无效（BR-06/BR-07） | 全量数据一起标准化 | 会把测试集信息泄漏进模型 |
| DR-11 | 部署位置 | 全本地（局域网 + 本机训练） | 无公网依赖、零成本、隐私最好、无外网可演示 | 云主机/公有推理 API | 引入成本与数据外发，需求不支撑（PRD 排除项） |
| DR-12 | 流量激励 | 固件默认内置 `ping` 到**局域网网关** | 实测不依赖外网，网关回 ICMP | 必须外部发包 | 仅在设备侧激励异常时才需要（备选 `external` + `traffic_gen.py`） |

## 3. 数据模型

本项目**不使用数据库**：数据 = 「设备读数」+「本地文件」。

### 3.1 实体

| 实体 | 关键字段 | 来源/落点 | 说明 |
|---|---|---|---|
| Device | 芯片 `esp32c6`、固件 `ESPectre Native 3.0.0`、IDF `v5.5.5`、IP、端口 `62587` | `GET /health`、`GET /device` | 自检（FR-01、AC-01） |
| WiFiLink | SSID、`band`、信道、`rssi_dbm` | `GET /wifi` | 频段校验（BR-01）与摆放判定（FR-02、BR-04） |
| Diagnostics | 流量收发计数、CSI 回调/接受计数 | `GET /diagnostics` | 链路是否真的在工作的客观判据 |
| **MapPoint**（参考地图中的一行） | `map_id, room, x_m, y_m, height_m, ap_id, ssid, band, channel, rssi_mean, rssi_median, rssi_std, rssi_min, rssi_max, n_samples, n_errors, ts_start, ts_end, operator, note` | `data/rfmap/<map-id>.csv` | **核心数据**（FR-03、FR-04）。每行 = 一个已实测点 |
| **ReferenceMapMeta** | 网格 `0,0,6,4,1`、点数、`seconds/settle`、高度、设备、`started_at` | `data/rfmap/<map-id>.meta.json` | 复现该份地图的配置（FR-04、NFR-03） |
| **SplitPlan** | 场景组（train/val/test 的 `map_id` 列表）、每图输入点坐标、隐藏点坐标、随机种子 | `data/rfmap/splits/<plan-id>.json` | **未实现**。固定划分，训练可用、评测不可改（FR-09~FR-11） |
| Normalizer | 均值/标准差（只来自训练集） | `models/<run-id>/norm.json` | BR-07（未实现） |
| GridConfig | 房间范围、网格间距、接收高度 | `models/<run-id>/grid.json` | 推理必须一致，否则拒绝出图（BR-09，AC-15） |
| ModelArtifact | 最佳权重、模型结构名、超参 | `models/<run-id>/best.pt`、`arch.json` | 可重新加载（FR-20、AC-15） |
| Prediction | 与网格同尺寸的 RSSI 数值网格 | 内存 → `outputs/rfmap/<run-id>/pred.csv` | 单通道输出（FR-15） |
| EvaluationReport | MAE、RMSE(dB)、推理时间、插值基线对比 | `outputs/rfmap/<run-id>/report.md` | 结论与置信口径（FR-17、FR-18、AC-14） |

### 3.2 输入张量约定（任务书要求，逐字对齐）

| 通道 | 内容 | 关键约束 |
|---|---|---|
| ch-0 | 稀疏 RSSI 图：只在输入点有真实 dBm 值 | **未测位置是占位值**，不得理解为 0 dBm / 无信号（BR-08、AC-09） |
| ch-1 | 观测位置标记图：标出哪些格子是"已知输入点" | 让模型区分"没测"与"测了但很弱" |
| ch-2 | 有效区域图：房间内/外 | 房间外用填充值，且不参与误差计算 |
| 输出 | 1 通道、与输入同尺寸的 RSSI 网格 | 线性输出 + 回归损失（DR-07） |
| 损失/误差 | **只在隐藏实测点（及任务书规定范围）上计算** | 观测位置标记必须参与掩码，未测位置不参与 |

### 3.3 关系与目录约定

```
Device 1---1 WiFiLink        电脑 1---N ReferenceMap(每份 = 1 个 map_id)
ReferenceMap 1---N MapPoint   ReferenceMap 1---1 ReferenceMapMeta
SplitPlan N---N ReferenceMap SplitPlan 1---1 Normalizer（按训练集算）
ModelArtifact 1---1 Normalizer + GridConfig + SplitPlan
Prediction N---1 ModelArtifact   EvaluationReport 1---1 Prediction
```

```
data/rfmap/<map-id>.csv              # 每点一行（已实测：ROOM-A-dp1 的 CSV 尚未产出）
data/rfmap/<map-id>.meta.json        # 网格/高度/设备/开始时间（已实测存在）
data/rfmap/splits/<plan-id>.json     # 划分方案（未实现）
models/<run-id>/{best.pt,arch.json,norm.json,grid.json,curve.csv}   # 未实现
outputs/rfmap/<run-id>/{heatmap.png,pred.csv,report.md}            # 未实现
```

### 3.4 访问规则

| 规则 | 内容 |
|---|---|
| 网络范围 | 仅局域网访问设备 `:62587`，不暴露到公网 |
| 凭据 | Wi-Fi 口令等**不得写入仓库**；配网信息存于设备 NVS（BR-14、NFR-07） |
| 个人数据 | 采集内容只含设备/网络/坐标/RSSI/时间；**不含图像与个人标识**，操作人可用代号（NFR-05） |
| 答案隔离 | **推理进程不得读取隐藏实测点/参考答案文件**；评测脚本与推理脚本分开（BR-05、AC-12） |
| 记录用途 | 数据文件用于报告复现，需注明采集日期、场地、部署与操作人 |

## 5. 失败处理

| 编号 | 失败模式 | 检测方式 | 期望处理 | 关联 |
|---|---|---|---|---|
| FH-01 | 设备不可达（连接拒绝/超时） | 自检 | 依次排查：不同网段 → AP 隔离 → 未上电 → IP 变更（重扫） | BR-02、AC-01 |
| FH-02 | 采样点全部读不到 RSSI | `n_errors` 计数 | 先查链路与流量激励，**不得用改统计口径掩盖**；该点标记为无效 | FR-06 |
| FH-03 | 单点过近（> -40 dBm） | 读 RSSI | 判"太近"，提示移到 3~5 m；**该行原样保存** | BR-04、AC-06 |
| FH-04 | 单点偏弱（< -70 dBm） | 读 RSSI | 判"偏弱"，如实保留并标注原因 | BR-04 |
| FH-05 | **整份地图全部不在 -40~-70** | 汇总统计 | 判该份"过强/过弱、无效"，提示重采；**不得报成"信号优秀"或"设备故障"** | AC-16 |
| FH-06 | 频段不是 2.4 GHz | 读 `/wifi` 的 `band` | 告警并提示重新配网，不把数据当有效 | BR-01 |
| FH-07 | 无外网 | 无法访问工具页 | 改走 curl/脚本路径（正式路径本来就离线） | BR-13、NFR-06 |
| FH-08 | 数据目录为空 / 某图隐藏点为 0 | 划分与评估前置检查 | 给明确空状态说明与下一步指引，不崩溃、不出空图 | BR-11、AC-17 |
| FH-09 | 非法网格/点位格式/不存在的 IP | 参数解析 | 明确报错 + 非零退出码 | BR-12、AC-17 |
| FH-10 | 同一 `map_id` 跨了多个集合 | 划分自检 | **报错**并指出冲突的 `map_id` | BR-06、AC-08 |
| FH-11 | 输入点与隐藏点有重叠 | 划分自检 | 报错并列出重叠坐标 | BR-06、AC-07 |
| FH-12 | 未测位置被当成 0 dBm | 张量构造检查 | 用观测标记区分；未测位置不参与损失与误差 | BR-08、AC-09 |
| FH-13 | 推理时的网格/高度与训练不一致 | 读 `grid.json` 比对 | 拒绝出图并说明差异 | BR-09、AC-15 |
| FH-14 | 测试误差异常小（远低于训练误差） | 评估报告自检 | 输出泄漏自查提示（同图泄漏/隐藏点进输入/插值用了完整参考数据） | BR-16、AC-18 |
| FH-15 | 隐藏点数量不足，误差不具代表性 | 划分自检 | 报告隐藏点数并要求增加，不给出"高置信"结论 | FR-11、OQ-06 |
| FH-16 | 训练不收敛（误差不下降） | 固定小样本预检 | 先排除数据与掩码问题，再调学习率/容量；如实记录 | AC-11 |

### 6.4 验证方式（怎么算通过）

| 验证项 | 判据 | 对应 AC |
|---|---|---|
| 设备与频段 | 返回型号/固件版本，且 `band=2g` | AC-01 |
| 链路质量 | RSSI 落在 -40~-70 dBm 判"合适" | AC-02 |
| 点位清单 | `--dry-run` 打印 35 个点位且不连设备 | AC-03 |
| 房子数据完整 | CSV 行数 = 已采点数；每行样本数 > 0；meta 字段齐全 | AC-04 |
| 断点续采 | 重跑只补缺、无重复坐标行 | AC-05 |
| 异常点保留 | 过强点被提示且**仍在 CSV 中** | AC-06 |
| 划分正确 | 无 `map_id` 跨集合、输入点与隐藏点无交集 | AC-07 |
| 划分自检能报错 | 人为制造冲突时**报错并指出 `map_id`** | AC-08 |
| 未测位置处理 | 未测位置带标记且不参与损失 | AC-09 |
| 标准化 | 参数文件只含训练集统计量 | AC-10 |
| 训练有效 | 固定小样本上误差下降 | AC-11 |
| 推理隔离 | 移走参考答案文件仍能出图 | AC-12 |
| 出图 | 统一色标 + 输入/隐藏点可区分 | AC-13 |
| 精度报告 | MAE/RMSE(dB) + 推理时间 + 同输入点插值基线 | AC-14 |
| 可重载 | 同一模型对同一输入给出同一地图 | AC-15 |
| 无效地图 | 整份异常时判"无效、需重采" | AC-16 |
| 空/非法输入 | 明确报错、非零退出、不出空图 | AC-17 |
| 泄漏自查 | 误差异常小时输出提示 | AC-18 |
| 结论边界 | 报告限定"该房间的新部署" | AC-19 |
