## 1. 项目摘要

| 项 | 内容 |
|---|---|
| 项目名称（课程立项名） | 基于无线信号的户型建模与 Wi-Fi 覆盖热力图生成（立项表项目 5，华为 2012 无线实验室） |
| 本轮 MVP 名 | **RF Map：用少量实测点位预测整间房的 Wi-Fi 信号分布** |
| 一句话描述 | 给刚搬进新房间的用户一套方法：**只测少数几个位置的 RSSI**，就生成该房间的 Wi-Fi 覆盖热力图，告诉用户哪里信号好、哪里是死角、路由器放在哪更合适。 |
| 代码仓库 | 本仓库（`lab-tools/` 采集与评估脚本 + `docs/` 文档 + `data/rfmap/` 数据） |
| 团队人数 / 当前阶段 | 【待填】 / 采集链路已实测跑通；参考地图数据开始采集、尚未完成 |

## 2. 问题与目标用户

| 项 | 内容 |
|---|---|
| 目标用户 | **主要**：刚搬入新宿舍/出租屋的学生或租户——只有一个路由器，不知道哪个角落能流畅视频、哪张床边是死角。**次要**：家庭组网/装维与售后诊断人员（与立项表需求来源一致）。 |
| 使用情境 | 搬家后第一次布置网络，或路由器换了位置、房间加了柜子隔断需要重新确认覆盖。用户手上有**一台 ESP32-C6 采集设备**和**房间尺寸**，但不想把整间房每个位置都测一遍。 |
| 现在会出的错 / 代价 | 只能拿手机逐点走测，凭信号格数或单点 RSSI 判断：**测一点看一个数**，测不完整间房；靠经验猜死角，猜错就要重新挪路由器再走一遍。场地越大越费时（实验场地约 146 m²，2 m 网格即 49 点）。 |
| 现有做法的缺口 | 缺"**用少量已测点推断未测位置**"这一步：要么逐点全测（成本高），要么只看当前所在位置（信息不全）；而且**没有可复查的误差指标**说明这张图有多可信。 |

**范围收敛**：立项表的上位课题（融合 CSI/信号强度/测距做**户型推断**、多频段、随门开关与家具移动**在线更新**）远超本轮 MVP。本提案只做其中**可验证的一小块**：已知房间范围，用少量实测 RSSI 预测该房间的二维覆盖；其余列入 PRD 第 3 节排除项。

## 4. 现有做法与缺口

| 现有做法 / 凑合方案 | 成本或问题 | 我们的缺口定位 |
|---|---|---|
| 拿手机逐点走测，看信号格或单点 RSSI | 只知道当前站的地方怎么样；覆盖全屋就要走遍全屋，且不同手机读数口径不一致 | 固定用同一台 ESP32 + 统一高度/朝向采集，读数口径一致、可复查 |
| 厂商 App 的"Wi-Fi 体检 / 信号检测" | 依赖特定机型与 App 版本；多数只给当前值或粗略分档，不给未测位置的估计，也没有误差口径 | 产出**整张二维覆盖图 + 隐藏实测点误差（dB）**，并附插值基线对比 |
| 人工逐点测量后手动画示意图 | 146 m² 场地 2 m 网格即 49 点，纯采样已约 12 分钟/份；环境一变就要重做 | 把要测的点压缩到少量输入点，其余位置由模型补全，并用留出的隐藏实测点验证补全是否可信 |

> 只写我们能证明的缺口；未核实的竞品缺陷不作断言。

## 5. 方案与 MVP 价值

| 项 | 内容 |
|---|---|
| 最小可用方案 | 在**已知房间范围**内按统一高度采集 **8–15 个点位**的 RSSI（一份部署 = 一份参考地图），由一个小型卷积网络一次输出该房间整张二维 RSSI 覆盖图，并报告预测误差。 |
| 支撑的完整用户任务 | 确认设备与链路 → 录入房间尺寸与接收高度 → 按清单在少量位置采点 → 生成整张覆盖图 → 判断"哪里最差、路由器摆哪更好" → 结果与误差一起留档可复查。 |
| 用户看到的最终结果 | 一张带**统一色标**的 RSSI 热力图（标出实测输入点、隐藏评估点及其误差）+ 精度报告（MAE / RMSE，单位 dB，含同输入点的插值基线对比与推理时间）。 |
| 与现有做法的差异 | ① 从"逐点全测"变为"少量点 + 模型补全"；② 误差**可量化、可复查**（以隐藏实测点为答案，不用插值结果冒充）；③ 采集读数口径统一。 |

**端到端草图**（细节见 PRD 第 4 节）

```
固定路由器位置 → 量尺寸贴网格 → 在少量点位放设备逐点采样（统一高度/朝向）
  → 落盘「带坐标的 RSSI 参考地图」(CSV + 元数据)
  → 划分场景组（不同部署）与 输入点 / 隐藏实测点
  → 用输入点训练/推理 → 输出整张二维 RSSI 网格
  → 还原为 dBm：热力图 + MAE/RMSE 报告（与简单插值对比）
  → 用户看到"哪个角落最差、换路由器位置后的效果"，数据与划分文件可复查
```

## 6. 可行性与风险

| 维度 | 现状 | 结论 |
|---|---|---|
| 时间 | 【待填：可用周数】 | 【待填】 |
| 技能 | **已有**：ESP32 烧录配网、局域网 HTTP 采集、curl、Python 3 标准库、逐点采集流程（均已实测）。**缺**：PyTorch 训练与数据划分的实操经验 | 采集侧低风险；**训练侧需学习成本**，须在 M4 前跑通一轮最小训练 |
| 数据 | 目标：同一房间 **≥3 份不同部署**参考地图，每份 ≥25 个实测点。**现状：0 份完成**（`ROOM-A-dp1` 仅有元数据） | **最高风险项**，见下方最大不确定性 |
| 设备 | ESP32-C6-DevKitC-1-N8 + ESPectre Native 3.0.0（IDF v5.5.5）+ 2.4 GHz 路由器（无外网可用）+ 充电宝供电 | 已具备且实测可用 |
| 访问权限 | 实验场地能否在采集期持续使用、路由器能否移动：**待确认**（OQ-01） | 影响多部署地图能否完成 |
| 预算 | 约 0 元（设备与场地为课程/既有资源；训练在本地笔记本完成） | 无外部费用 |
| 外部依赖 | ESPectre 固件与设备接口可用性、2.4 GHz 限制、场地噪声与人员走动、采集时的人员遮挡 | 可控，但需在采集规范中固定（PRD BR-03） |

**最大不确定性（只写一个）**

| 项 | 内容 |
|---|---|
| 最大不确定性 | 我们只有**一间房间、一个 AP**：模型学到的究竟是"**可泛化的空间补全**"，还是"把这一张图记下来"？任务书明确：只有一张固定地图时，反复遮挡只能证明程序能跑，**不能证明模型会补全未知地图**。 |
| 如何在早期查清 | ① 同一房间采 **≥3 份不同路由器部署**的独立地图（dp1/dp2/dp3），按**部署整组**划分训练/验证/测试；② 每张图内固定划分"输入点 / 隐藏实测点"，测试集抽点结果固定并保存；③ 先用少量固定样本检查误差能否下降；④ 同一组输入点同时喂给**简单插值**与网络，比较 MAE/RMSE。若网络无法优于插值，就如实报告——任务书明确**不要求**神经网络必然优于插值。 |
