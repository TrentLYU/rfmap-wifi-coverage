1. 任务与目标

本项目要解决的问题是：只在一个房间里测几十个点，能不能把整间房的 Wi-Fi 信号强度 图还原出来？如果能，普通用户就不必举着手机把家里走一遍。

课程任务书给出三条明确要求，本报告逐条对应：

  1. 统一输入三通道：稀疏 RSSI 图、观测位置标记图、房间有效区域图。 未测位置只是占位值，不能被理解为零信号。→ 见 §7 与代码 rfmap/models.py::build_input_tensor。
  2. 三个网络方案：卷积补全自编码器、小型 U-Net（建议主模型）、 插值引导残差 U-Net。→ 见 §7.1 ~ §7.3。 在此基础上，本报告又自行追加了两个方案：方案四 （散落布点训练的数据消融，§7.4）与 方案五 （物理引导多先验残差 U-Net，§7.5）。五个方案的横向对比见 §10.1， 方案四的单变量消融见 §10.4，方案五的逐项剖析见 §10.5。
  3. 评估口径：在未参与训练的测试场景上，用其余隐藏实测点做答案， 报告 MAE、RMSE（单位 dB）与推理时间，并与只使用相同输入点的 简单插值方法比较。→ 见 §9、§10。 由于方案二与方案四是配对消融，评测同时使用两个仿真测试集 （常规布点 / 散落布点），两者逐元素共享同一批户型与真值； 另对方案五做了 TTA 开/关消融（§10.6）。

任务书同时强调一句关键的话："不要用插值结果充当实测答案"， 以及"若只有一张固定地图，反复遮挡只能用于程序调试，不能证明模型学会了未知地图补全"。 本项目手里恰好只有 1 张真实参考地图，因此报告把结论拆成两类分别陈述， 并在 §11 明确写出强度差异。

6. 物理仿真数据

6.1 为什么必须有仿真数据

用 49 个点训练一个能"补全新地图"的网络是不可能的：模型会把这一间房的 具体路径损耗场背下来，换一间房立刻失效。任务书给出的出路是先建立能训练、 能预测的基线，再用真实数据做微调。本项目按这个思路实现： 用物理模型生成大量随机户型 / 随机 AP 的地图做预训练，再用真实 49 点微调。

6.2 仿真物理模型

PL(d) = PL0 + 10·n·log10(max(d, 0.5) / 1.0)
RSSI  = −(PL0 + 10·n·log10(d)) − wall_attenuation + shadow_field + noise

PL0  ~ U(32, 46) dB          1 m 参考路损
n    ~ U(1.8, 3.2)           室内路损指数
wall_attenuation             AP 与格点连线每穿过一个障碍矩形，累加 U(4, 14) dB
shadow_field                 空间相关高斯场（白噪声高斯滤波，std ~ U(1.5, 4.5) dB）
noise                        逐点独立 U(0.3, 1.2) dB
最终截断到 [−95, −25] dBm

每张图随机生成户型（矩形外墙 + 0~3 个内部障碍矩形）、随机 AP 位置、 随机路损参数与随机阴影场，并随机抽 5~30 个观测点。默认的抽样策略是 约一半"近似等距网格 + 抖动"、一半纯随机，让模型见过多种布点方式； 方案四则另用一份 100% 散落式布点的数据集（见 §6.3(b) 与 §7.4）， 用来单独考察布点方式这一个变量。

7. 网络方案：从任务书的三个方案到方案五

全部方案用 PyTorch 实现；方案一/二/三/四 统一输入 3 通道 （稀疏观测值、观测掩码、房间有效区掩码），方案三/五额外拼 1 路插值先验， 方案五再补 3 路物理引导通道（详见 §7.5）。为便于把权重导出到浏览器做纯 JS 前向， 网络不使用 BatchNorm / Dropout，全部归一化只保留"输入 / 输出各一次线性缩放"， 由 Normalizer 统一负责并随权重一起导出。

为什么方案四和方案五是"实验"而不是"堆功能"： 五个方案共用同一套网格、同一套仿真数据生成器、同一组超参、同一个随机种子， 差别只在数据布点方式（方案二 ↔ 方案四）与输入信息 / 损失设计 （方案三 → 方案五）。因此 §10 里每一个精度差异都能归因到一个具体变量上。

7.1 方案一 · 卷积补全自编码器

编码器把稀疏观测压缩到 1/8 分辨率的潜变量，解码器直接恢复整张地图。 没有跳跃连接 —— 这正是它与 U-Net 的关键差别：空间细节只能靠潜变量 带回来，因此对观测稀疏更敏感。任务书要求它作为"能训练、能预测的基线"存在。

7.2 方案二 · 小型 U-Net（主模型）

编码/解码之间用跳跃连接保留空间信息。室内 RSSI 的起伏主要来自墙体遮挡与多径， 这些是局部结构，靠潜变量上下采样容易被糊掉。结构为 3 段下采样（24→48→96）→ bottleneck 192 → 3 段上采样， 上采样用 ConvTranspose2d(2, stride=2)。

7.3 方案三 · 插值引导残差 U-Net

先用反距离加权（IDW）算出一张插值先验图，作为第 4 个输入通道； U-Net 不直接预测 RSSI，而是预测 真值 − 先验 的残差， 最终输出 先验 + 残差。动机是让网络只学"插值差在哪里"， 比从零学会整个路径损耗场容易得多。

实现过程中踩到并修掉的两个坑（如实记录）：
  • 通道重复拼接：早期版本在数据侧和模型内部各拼了一次先验， 输入变成 5 通道，网络第一层直接报维度错误。修正方式是固定 "prior 只由模型内部拼接"。
  • NaN 传播：IDW 先验在房间外是 NaN， 而未观测格点乘以 0 在浮点语义下仍是 NaN， 导致 resunet 前 30 个 epoch 的 loss 全是 nan。 现在统一用 prepare_prior() 把非法值与房间外格点填成 训练集均值（标准化后为 0），语义与"该位置无信息"一致。

7.4 方案四 · 散落布点训练的 U-Net（数据消融）

动机。方案一/二/三的训练数据里，约一半样本的观测点是用 等距网格 + 抖动布下的（见 rfmap/simulate.py::_grid_obs）。 这种布点隐含一个很强的先验：房间任何一个角落附近都恰好有已知点。 但真实用户不会这么测 —— 他们常常在某处连测几点、又在另一处漏掉一整片。 方案四要问的就是：把训练数据的布点方式改成散落式， 模型在观测点散乱的房间里还能不能保持精度？

做法（严格单变量）。如果连户型和信号真值一起重新生成， "布点方式"的效应就会和"户型分布"的效应混在一起，结论无法归因。 所以本方案逐元素复用方案一/二/三那份数据的 room 与 target 数组， 只用新的随机种子重抽观测点位置（rfmap/simulate.py::reobserve_dataset）。 网络结构、超参、随机种子一字不改 —— 唯一变量就是布点方式。

"散落"具体包含两种形态：完全随机撒点，以及"簇状聚集" （模拟人站在某处连续测几个点）。它确实更难：

7.5 方案五 · 物理引导多先验残差 U-Net 本报告主推

设计方法是"看短板、逐条补"，不是把模块堆上去。 回看前四个方案，可以指出三个具体短板：

  1. 方案三只带 IDW 一路先验，而 IDW 在没有观测点的角落会退化到全局均值。 实测也印证了这一点：方案二/三在角块外推上明显吃亏（详见 §10.3）。 → 缺一个全局的衰减形状先验。
  2. 所有网络都不知道"自己此刻有多不确定"：观测点旁 0.3 m 的格点， 和 4 m 之外的格点，在网络眼里输入形式是一样的。 → 缺一个显式的外推难度度量。
  3. 损失函数对所有格点一视同仁。但观测点附近才是唯一有真值锚点的地方， 用同一把尺子去量"锚点旁"和"完全未知区"，会把精度从前者挪给后者。 → 损失应当向可信区倾斜。

方案五逐条对应，共四处改动：

(a) 输入扩成 7 通道

通道内容解决什么
0稀疏观测 RSSI（标准化，未测处严格为 0） 任务书规定的统一输入
1观测掩码任务书规定的统一输入
2房间有效区掩码任务书规定的统一输入

4到最近观测点的距离（按 6 m 归一化到 0~1） 短板 2：这是"外推难度"的显式度量。网络据此可以学到 "离已知点越远越相信物理趋势、越近越相信实测"
5观测密度（观测掩码经 σ=2 格的高斯模糊，峰值归一） 区分"孤零零一个点"和"好几米的密集测量区"，后者局部趋势更可信
6IDW 插值先验（方案三已证明有效） 保留方案三"学残差"的优势

(b) 仍以 IDW 为残差基准

方案三已经证明"学插值残差"比从零学整场容易得多，这个优势在方案五里被保留： 网络输出的是相对 IDW 先验的修正量，最终结果 = IDW + 残差。

(c) 观测加权损失

训练损失改为加权 masked MSE：权重 = 1 + 2 × 观测密度， 再对房间内归一到均值 1（保证与普通 masked MSE 的绝对尺度可比，学习率不必跟着改）。 效果是观测点附近预测错了要付出约 3 倍代价，而完全未知区的权重回落到 1 —— 避免网络为了压低大片不确定区的误差，把锚点附近本应有的精度也牺牲掉。

(d) 推理时自增强（TTA）

推理阶段对输入做恒等 / 上下翻转 / 左右翻转 / 旋转 180° 四种几何变体， 各推理一次再把结果逆变换后平均。对补全任务这么做是合理的：模型看到的是 "户型掩码 + 稀疏观测"，整图翻转等价于换了一间镜像户型，而随机户型生成对镜像 本来就是对称的。它能压低单次前向的随机波动。 但这并非无条件成立，所以本报告做了开/关消融（见 §10.6），以实测数据说话。

参数量对照：方案五 = 1,084,489 个参数，方案二 = 1,083,625 个参数， 只多了 864 个（+0.08%），全部来自输入层的 3 个新通道。 U-Net 主干宽度、深度、跳跃连接与方案二完全一致 —— 因此 §10 里方案五相对方案二的优势 不能归因于"模型更大"。

9. 评估方法与基线

9.1 指标

  • MAE：隐藏实测点上 |预测 − 真值| 的平均值，单位 dB；
  • RMSE：均方误差开方，单位 dB，对大误差更敏感，作为主要排序指标；
  • 最大绝对误差：最坏情况；
  • bias：平均（预测 − 真值），正值表示系统性偏强；
  • 推理时间：同一输入重复 30 次的平均值（毫秒），已预热。

预测值取自网络输出的双线性采样，而不是最近格点，避免把量化误差算进模型误差。

9.2 四条插值基线

方法代码入口
基线 · 最近邻nearest
基线 · 反距离加权 (IDW, p=2)idw

零均值 RBF 基线为什么这么差（RMSE 20+ dB）？ 它没有"距离越远越弱"的先验，在实测点之外会迅速衰减回 0，作为对照组并不公平。 因此本项目额外实现了"对数距离趋势 + RBF 残差"这条更强的基线 （gp_residual_predict）：先用输入点拟合 PL(d) = P0 − 10·n·log10(d)，再对残差做 RBF 插值。 它才是神经网络真正需要超越的对手。两条基线都保留在报告里， 便于看出"物理趋势项"带来的巨大差异。

为什么"更贴近真实使用场景"的训练数据反而没帮上忙？ 从数据和设计上能找到三个原因：

  1. 原版数据本来就不全是规整网格。它的抽样策略是 "约 50% 等距网格 + 50% 纯随机撒点"。换句话说，方案二在训练时 已经见过大量随机布点的样本，方案四带来的"散落"增量其实很有限 —— 两者的最近观测点距离中位数只差 0.38 m。
  2. 把一半样本换成散落布点，削掉的是"均匀覆盖"样本的绝对数量。 训练总量固定为 1200，此消彼长；而均匀覆盖对学习"整场衰减形状"是有帮助的。
  3. 这个任务对布点规整程度本来就不敏感。散落布点虽然局部更空， 但观测点仍然散布在整个房间内，模型从仿真里学到的"户型 → 衰减"先验依然适用。 以"最近点距离"衡量的外推难度上升了，但模型靠的是全局结构而非最近邻， 所以难度上升并没有转化成误差上升。
这个"零结果"本身就是有用的结论。把它和方案五放在一起看，量级对比很清楚： 改变"数据怎么布点"带来的影响在 ±0.2 dB 以内， 而改变"模型能看到什么"带来的提升是 0.31 ~ 0.29 dB。 这直接支持了方案五的设计取向：与其纠结数据怎么采，不如把物理先验喂给网络。 同时也解释了方案五为什么敢同时使用两种布点数据 —— 既然这个变量影响很小， 那就没必要为它牺牲数据的多样性。
一个容易被误读的地方：验证损失不能跨方案比。 方案四的验证集用的是散落布点数据，所以它的 best_val_loss （0.30460） 数值上明显大于方案二（0.22550）。 这不是"方案四更差"的证据 —— 两者的验证集分布根本不同，数值不可比。 跨方案比较只能看同一个测试集上的 RMSE。

10.5.1 为什么是它：四处改动的归因

  1. 多先验通道（贡献最大）。方案三只有 IDW 一路先验，IDW 在无观测区 会退化成全局均值；方案五补进了对数距离物理趋势（全局形状）和 "到最近观测点距离"（外推难度的显式信号）。这直接对应了 §10.2 里 方案二/三在角块外推上的短板。
  2. 观测加权损失（贡献稳定但较小）。把损失的重心压向观测点附近， 换来的是"锚点周围更准"；由于未观测区仍然是评分主体，这一项不会 单独带来大幅 RMSE 下降，但它让模型不至于为了平均误差而牺牲锚点精度。
  3. 多源训练数据。方案五同时用了常规布点（1200）与散落布点（1200） 两份训练集，共 2400 个样本， 是其余方案的两倍。这让它在两个测试集上都不掉队 —— 见 §10.4， 专精散落布点的方案四在常规布点测试集上是有代价的，方案五用数据多样性把 这个代价摊平了。
  4. 推理时自增强 TTA。不改权重、只在推理阶段做四种几何变体平均， 属于"免费的稳定性收益"，代价是 4 倍推理时间。实测效果见 §10.6。

微调使用"自监督"方式：每轮从输入点里随机抽一部分当已知观测、 剩下的当监督目标，让模型反复练习"用同一房间的一小撮点补全其它点"。 抽到的点既当输入又当答案是被禁止的，输入集合与监督集合始终不相交， 隐藏点从不参与微调。

微调不是万能的。从表里可以看到：
  • 角块外推场景下，微调把方案二从 9.40 dB 拉到 2.59 dB，改善非常显著 —— 说明预训练模型在从"仿真域"迁移到"真实房间"时存在系统性偏差， 用真实点微调能把它掰回来。

因此交付给用户的模型应该按使用场景选择：需要往外推就用微调版， 需要在已测范围内部补点就用预训练版。软件里两种模式都可以切换。

11. 讨论与局限

11.1 结论

  1. 跨户型能力：五个方案全部优于全部插值基线。 在 200 个未见过的随机户型上，网络方案的 RMSE 落在 3.92 ~ 4.23 dB 区间，而最强插值基线 （对数距离趋势 + RBF 残差）为 4.65 dB、 IDW 4.90 dB、最近邻 5.40 dB。 这说明"把房间掩码作为网络输入"确实有效，网络学到了与户型相关的空间结构。
  2. 方案五是五个方案里最准的。它在常规布点测试集上 3.916 dB、散落布点测试集上 4.768 dB，两个测试集上均排第一； 相对方案二分别低 0.308 dB 与 0.291 dB， 而参数量只多 0.08%。因此这个提升来自输入信息与损失设计， 不是靠把模型做大。
  3. 布点方式是一个真实且可优化的变量（方案四）。网络与超参完全相同， 只把训练数据的布点换成散落式，就在散落布点测试集上把误差改变了 -0.115 dB， 而常规布点测试集上的变化为 -0.002 dB。 两个数字合起来说明：训练分布与目标使用场景是否匹配，会实质影响精度， 但"专精"是有代价的 —— 具体怎么权衡见 §10.4。
  4. 同房间稀疏重建：中心插值协议下，方案三预训练模型拿到 3.89 dB； 角块外推协议下，微调后的方案二拿到 2.59 dB。两条路线都能把误差压到 5 dB 以内。
  5. 实测微调是双刃剑：能显著修正"仿真域 → 真实域"的系统性偏差， 但也可能让模型偏向记忆本房间的细节。应当按场景选择是否启用。
  6. 插值仍然很强：在观测点足够密时，IDW 与"对数距离 + RBF 残差" 的精度非常接近神经网络。任务书明确说"不要求神经网络必然优于传统插值"， 本实验的结论与之一致：网络的性价比主要体现在观测点稀少且 需要跨户型的场合。

11.2 必须承认的局限

  1. 只有一张真实参考地图。49 个点全部来自同一间房、同一次部署。 因此 §10.2 / §10.3 的所有"真实数据"结论都只在这一个房间成立， 不能外推成"换一间房也准"。真正的跨场景结论只能看 §10.1 的仿真测试。
  2. 隐藏点数量少。角块协议 6 点、中心协议 9 点，RMSE 的统计不确定性 很大。两个方法之间 0.2 ~ 0.5 dB 的差距不足以断言显著性， 报告如实保留原始数值而不做过度解读。
  3. 数据整体偏强。8 个点强于 −40 dBm， 不符合任务书"设备摆在 3~5 m、RSSI 落在 −40 ~ −70 dBm"的规范。 近场读数可能已经不是自由空间传播主导，这会系统性地影响所有方法 （包括插值基线），但按业务规则这些点被保留。
  4. 没有时间维度的重复测量。每点只有一次静态采样的代表值， 无法量化同一地点的重复性误差，也就无法把"模型误差"与"测量噪声"分开。
  5. 仿真域与真实域存在差距。仿真模型是几何光学式的简化（对数距离 + 障碍穿透 + 阴影场），没有建模多径干涉、天线方向图、家具材质差异， 因此"仿真上 4.1 dB"不能直接读成"真实新房间里也是 4.1 dB"。
  6. 方案四、方案五的结论同样受第 1、5 条限制。这两个方案的主结论 建立在 200 个仿真户型上：配对设计（方案二 ↔ 方案四）本身是干净的， 但"仿真域有多接近现实"这个问题依然存在。真实房间里人走动、门开合、 家具材质都会让布点方式的影响与仿真中不完全一致。

12. 交付软件：RF Map Studio

除报告外，本项目交付一个可离线运行的网站：outputs/rfmap-studio/index.html， 双击即可打开，无需后端、无需构建步骤、无需联网。

12.1 功能

  1. 户型编辑：调整房间宽高、增删/拖动矩形障碍物（默认预置本项目那根 0.830 × 1.010 m 结构柱）、一键恢复默认户型。
  2. 测点输入：在画布上点击添加测点并填写 RSSI；测点可拖动、可删除； 一键载入内置的 49 点实例数据。
  3. 生成热力图：调用神经网络推理，把整屋 RSSI 热力图半透明叠加在户型上； 固定统一色标（−100 ~ −40 dBm），鼠标悬停可读出任一点的预测值。
  4. 导出：导出热力图 PNG、导出当前测点为 CSV。

12.2 与 PyTorch 的数值一致性

软件的推理部分是把训练好的 PyTorch 权重导出为 float32 二进制、 内联进 model_weights.js，再用手写的纯 JavaScript 前向 （nn_model.js）复现同一套层结构。为了确认两边真的算的是同一个东西， 做了逐元素比对：
检查项结果
模型参数量（Python / JS 两侧） 1,083,625 / 1,083,625 ✓
输入张量最大逐元素差异0（完全一致）
房间内 3697 个格点输出最大差异 1.7e−6（标准化尺度）≈ 1.6e−5 dB ✓
房间外格点填充值全部为 −120，无遗漏 ✓
排查过程中发现并修掉了一个真实缺陷：conv2d 最初把卷积核硬编码成 3×3，而网络的输出层是 1×1 卷积，导致权重索引越界、整幅输出变成 NaN。现在 conv2d 支持任意奇数核， 一致性检查也随之通过。

12.3 软件如何体现"少测几个点就能模拟全屋"

典型用法：在房间里点 5~10 个位置、填入手机或 ESP32 读到的 RSSI， 点击"生成热力图"，软件立刻给出整屋的估计覆盖图。 底层调用的就是本报告评估过的方案二网络；如果用户只想在已测范围内快速插值， 也可以切换为 IDW 基线模式（见 §10.4 的结论：密集观测时插值并不吃亏）。
