# RF Map Studio · 使用说明

> 一个**可离线运行**的 Wi-Fi 覆盖预测小工具：在户型图上点几个测点、填上 RSSI，
> 就能得到整间房的信号强度热力图。
> 目录：`outputs/rfmap-studio/` ｜ 入口：`index.html`

---

## 1. 快速开始

1. 打开文件夹 `outputs/rfmap-studio/`；
2. **双击 `index.html`**（推荐 Chrome / Edge / Safari）；
3. 页面打开后点击左上角 **"载入示例数据（49 点）"**，再点 **"生成热力图"**，
   即可看到本项目那间 12.643 × 11.731 m 房间的完整覆盖图。

> 不需要安装任何东西，不需要联网，也没有后端服务。所有计算都在浏览器里完成。

## 2. 界面区域

| 区域 | 作用 |
|---|---|
| 顶部信息栏 | 显示房间面积、当前测点数、上次推理耗时（毫秒）、色标范围 |
| 左侧控制面板 | 户型编辑、测点输入、生成/清除热力图、导出 |
| 中央画布 | 户型俯视图 + 测点 + 叠加的 RSSI 热力图 |
| 右侧色标条 | −100 dBm（深蓝）→ −40 dBm（深红），刻度随机显示 |

**朝向约定**：画布上的 x 轴是**反向**的（原点在右下角、x 数值增大向左），
与现场采集时的方位一致。这样从画布上读到的位置可以直接对应到实际房间。

## 3. 操作流程

### 3.1 设置户型

- 直接修改宽/高，默认 `12.643 × 11.731 m`（本项目实测房间）；
- 拖动或输入矩形障碍物的尺寸与位置。默认已按户型图预置那根
  **0.830 × 1.010 m 的贴墙结构柱**（x ∈ [11.813, 12.643]、y ∈ [5.761, 6.771]）；
- 点 **"恢复默认户型"** 可以随时回到初始状态。

> 户型信息是**真的**参与计算的：房间掩码（含障碍物）会作为神经网络的输入通道，
> 而不是只画着好看。这也是本工具能在陌生户型上工作的原因。

### 3.2 输入测点

- 在画布上**点击**任意位置 → 弹出输入框 → 填写该点实测的 RSSI（−100 ~ 0 dBm）；
- 测点可**拖动**调整位置、可**删除**；
- 想先用现成数据，点 **"载入示例数据（49 点）"** 一键载入本项目的实测数据；
- 测点数会实时显示在顶部。

### 3.3 生成热力图

点 **"生成热力图"**，稍等片刻（首次约 0.5~1 秒，之后更快），
画布上会叠加出整间房的 RSSI 分布。把鼠标移到画布上可读出该点的预测值（dBm）。

### 3.4 导出

- **导出 PNG**：把当前热力图连同户型一起存成图片；
- **导出 CSV**：把当前所有测点（坐标 + RSSI）导出为表格。

## 4. 它背后是什么模型

- **网络结构**：方案二 小型 U-Net，**1,083,625 个参数**，输入 3 通道
  （稀疏观测值 / 观测掩码 / 房间有效区掩码），输出单通道 RSSI 网格（64 × 64）。
- **权重来源**：在 1200 张物理仿真地图上预训练（`models/unet/model.pt`），
  导出为 float32 二进制内联在 `model_weights.js`。
- **前向计算**：纯 JavaScript 手写实现（`nn_model.js`），与 PyTorch 逐元素比对通过 ——
  房间内 3697 个格点的最大差异为 **1.7e−6**（标准化尺度）≈ **1.6e−5 dB**。
- **标准化参数**：mean = −55.586 dBm，std = 9.673 dB（只从训练集拟合，随权重一起导出）。

### 关于精度，请看实验报告

- 在 **200 个未见过的随机户型**上，本网络的 RMSE 为 **4.25 dB**，
  优于 IDW（4.90 dB）与"对数距离趋势 + RBF 残差"（4.65 dB）；
- 在**本项目这间房**的中心插值场景下，预训练模型 RMSE **2.86 dB**；
- **注意**：这些数字来自特定实验条件，不构成"在你家也一定准"的承诺。
  详细的口径、局限与原始数据见 `outputs/RF覆盖预测实验报告.html` 第 10、11 节。

## 6. 已知限制

1. **网格固定为 64 × 64、cell = 0.2 m**（覆盖 12.8 × 12.8 m）。
   如果把房间拖到大于 12.8 m，超出部分不会有热力图。
2. **房间外固定填 −120 dBm**，绘图时会做裁剪，不会把无效区混进贴墙一圈。
3. **没有后端**，不支持保存/分享工程文件；刷新页面会重置。
4. **当前只内置了方案二 U-Net 的权重**。其余四个方案（含本报告主推的方案五）
   尚未接入前端：
   - 方案五需要 7 个输入通道（多 3 路先验图：对数距离趋势、到最近观测点距离、
     观测密度），要在浏览器里复刻就得再用 JS 实现这三个通道的计算；
   - 方案三/五还需要在推理时额外提供 IDW 先验通道。
   报告里给出了这些方案的精度优势与代价对比（§10.5），接入是后续工作。
5. **未在真机浏览器上做人工视觉验收**：已实测的部分包括资源加载（HTTP 200）、
   IDW 与神经网络推理的数值正确性、坐标与翻转映射的数值一致性，以及交互流程；
   但画布的最终观感建议你自己打开确认一次。

## 7. 与实验报告的关系

本软件是实验报告 §12 描述的交付物。报告里五个网络方案的精度对比
（`outputs/RF覆盖预测实验报告.html`）决定了这里该用哪个权重：

- 方案五在跨户型补全上最准（比方案二低约 0.3 ~ 0.5 dB），但要付 7 通道的
  实现代价；
- 方案二结构最简单、参数量最少，且在本前端的数值一致性验证上已经跑通，
  因此当前版本以内置方案二为准。

若你要把方案五接进来，需要扩展的接口是 `nn_model.js` 的输入张量构造部分
（在 3 个基础通道之后追加 3 路先验通道），U-Net 主干与前向逻辑可以原样复用。
